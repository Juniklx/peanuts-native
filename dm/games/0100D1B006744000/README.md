# Crash Bandicoot N. Sane Trilogy (`0100D1B006744000`)

<!-- PEANUTS: experimental Android profile, imported from DroidPlay Core for a separate test build; no S24 FE runtime claims. -->

## Provenance

The source-only public profile and shader input metadata are from [DroidPlay Core, commit 8115593e](https://github.com/enjoyerofslop/droidplay-core/tree/8115593e8a7f9ebfa0659008a1accadb9c79a8e9/dm/games/0100D1B006744000) (MIT license). The original [game note](https://github.com/enjoyerofslop/droidplay-core/blob/8115593e8a7f9ebfa0659008a1accadb9c79a8e9/dm/games/0100D1B006744000/README.md) documents the Switch **base game v0 / 1.0.0**, SDK 3.5.3, Vicarious Visions' Alchemy engine, with `main`, `subsdk0` (GLSLC) and `sdk`.

**External evidence:** The DroidPlay Core author reported a Galaxy Z Fold 8 (Adreno 840, Android 17) reaching N. Sanity Beach, controlling Crash and continuing a saved game, at the game's original ~30 FPS. This is **not** a result from the Galaxy S24 FE or this Peanuts Native fork.

The profile describes **1,635 shader entries**: 1,623 in `archives/shaders_nx.pak`, 10 in `main`, and **2 generated by the game's GLSLC** during startup. These are public indexing tables, not a distributable game or precompiled shader library. On-device Prepare may need its runtime shader-capture phase to generate the two GLSLC results from the user's own game.

Peanuts Native already has an Alchemy IGA v13 shader reader used for Crash Team Racing Nitro-Fueled (`dm/gfx/tools/shader_split.py`). **The first S24 FE Prepare failed after completing code rewrite:** 166 of 166 archive files reported `igArchive version 12: only 13 is known`. The message to dump the game again is generic and **does not establish data corruption**. This branch now imports DroidPlay Core's separately validated, bounds-checked **v12 reader** (`dm/gfx/tools/iga.py`) and routes v12 archives to it; the existing v13 reader is unchanged. Synthetic fixture test `dm/tools/tests/test_split_iga12.py` checks both compressed and uncompressed v12 shader entries. The real S24 FE dump has **not yet been successfully re-split with this fix**, so end-to-end pack, GPU compatibility, controls and the dynamic GLSLC capture are still unverified.

## Experimental Android plan — Galaxy S24 FE

1. Build an **isolated** test APK `dev.nxnative.android.crashnsttest`; never update the official Peanuts or any TUNIC test app.
2. Import the user's own **base Switch 1.0.0** dump into this app and run its on-device Build/Prepare. No game assets, compiled shaders, packs, keys or firmware go in GitHub.
3. Capture Prepare output, including any run-time GLSLC capture / rewriter error. This experimental branch includes a narrowly restricted, last-resort **general rewriter fallback** for the table-base-after-guard form in [nxnative #396](https://github.com/seedds/nxnative/issues/396): `jump table 997b78`. The alternative zero-extended index form (`efcc2c`) was already supported by the Peanuts rewriter. The fallback is adapted from public DroidPlay Core work, checked only after existing recognizers fail, and has **not** been tested against the user's game dump or on the S24 FE. Preserve a log on failure.
4. If the pack builds, test intro, menu and N. Sanity Beach with a physical gamepad, audio, graphics, saves and GPU driver. Gather `Share log` on failure.
5. Initially leave the game's original **30-FPS** presentation behavior. Do not infer 60/120 FPS from the TUNIC experiment: the games have different engines.

**Not yet verified on S24 FE:** boot, FPS, Vulkan graphics, RAM, stable save data or gamepad. Memory values in `game.tsv` are inherited from the DroidPlay Core provisional survey (including `app_pool 0xCD500000`) and are not S24 FE measurements. They must not be replaced with TUNIC's 2-GiB pool without evidence.

The title is not added to `peanuts/release-titles.txt`; this experiment is not an official supported-game claim.
